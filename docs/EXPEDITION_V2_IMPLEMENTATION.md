# 谷地营火 · 实现与验证边界

## 实现

模型以0.25秒固定步推进，前台单帧最多接受0.1秒，卡顿不补算。隐藏标签页或窗口失焦暂停，无离线生产。库存、资源节点、携带、已交付、消耗和损失分开记账。三个建设位置固定；建筑工人施工完成恢复原任务。军事结算在公开波次抵达5秒后进行，守军数量与哨塔降低穿透，守军承受损耗；严重穿透可能使相应采集路线工人阵亡。

每个操作通过统一模型命令执行并记录 tick。存档只保存关号、tick及合法指令日志，恢复重放不信任库存/生命快照。独立存档键 `atlas-expedition-v2-valley-20261018`；坏记录不覆盖，需用户明确重开确认。恢复活动局先暂停。浏览器拒绝存储时明确提示，当前页仍可运行。没有修改其他游戏或 v1 存档。

DOM 控制器测试为最小DOM桩，执行实际HTML对应控制器回调；不等同原生浏览器布局、键盘焦点行为、图像解码或触屏测试。模型普通策略没有注入资源/生命或修改规则。故障夹具与普通策略报告分开。

## 验证边界

- 普通策略：三段军队优先、三段经济优先；正常资源通关及闲置失败记录。
- 模型：每步双资源守恒、原子消费、有限节点耗尽、建筑占工/货物交付、调兵延迟、袭击阶段、终态冻结、存档重放、坏存档拒绝。
- 独立模型审查和最小DOM控制器记录见 `docs/expedition-v2-qa/`。
- 当前没有本候选的真实浏览器通关、手机操作、声音、性能或玩家品质验收；发布后正常UI实玩单独记录。插画文件检查和离屏合成不冒称浏览器截图。

## 手动复核建议

在宽屏正常开始第一段，分工/建筑/招募与两路调动并记录结果；一次失败或重试；载货或建设中刷新，确认暂停恢复且库存不跳变。窄屏检查地图、库存、下一步按钮和终局可见；独立说明页与所有图片加载。无需为了追胜无限重跑。
