## 本轮正常UI

公开Pages页面，Windows桌面既有Playwright Chromium，1440×1050和390×844 CSS视口、独立新上下文；窄屏启用移动/触摸能力模拟，不是真机。静音后正常开始/教程，滑杆点击与Home选−68度，再正常点击发射。每个视口自然6球耗尽5发预算（第二球接回一发）、剩3目标、325分、1次结算。

失利后正常点击“看看庭院”：结果层隐藏，游戏快照和本机存储原字符串不变；焦点移到外部重新入庭。直接正常键盘Enter回到首庭准备态：5发、能力2次、0分/0出手/0结算、无弹球；点击开始后暂停并刷新，资源与空弹球保留。没有位置、时间、球数、存档、胜负或分数注入，也没有修改规则/难度。

本轮从空纪录起步，没有为测试关闭路径重复先赢一局。非空最好1555保留的证据仍是既有pinfall-loss-qa，本批不扩大那项结论。没有新fixture测试或故障注入。

最终两视口页面/控制台/HTTP/请求失败均为空。首次脚本在自然6球失利后，因误用不存在的#status元素而中断，未到关闭路径；改用实际#battle-status后正常完成。保留[首轮原记录](harness-failed-attempt.json)和[错误说明](attempts.json)，不把工具错误当产品缺陷。

## 一个已观察到的下一候选

390CSS下，“看看庭院”后的焦点在`#restart`，其矩形顶部1574.97CSS像素、高42；视口只有844像素，当前scrollY38，因此焦点目标在屏外。1440CSS对应按钮顶部810.08、高34，在1050高视口内。两种情况Enter都能重试，场地下方也有R提示；这是焦点可见性候选，不是卡死、重试丢失或存档问题。

下一批可设计“查看时焦点留在可见场地，同时能明确重试”的最小处理；不能直接把页面滚到远处按钮而损失查看庭院的目的。本批仅记录，不擅自扩大修复范围。
