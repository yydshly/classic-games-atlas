# 堡垒v2：基地受击反馈

本轮只交付一项玩家可见改进：**基地受击时明确指出受损对象、剩余耐久和回防建议。** 基线 `9c8b107f1ae42b4235d1af9bd57e1476fd0ce792`。保持本作原创基地防守定位；沿用[既有参考与差异说明](../../versions/v2/games/fortress/NOTES.md)，参考Battle City共同护卫基地的目标。两张六敌原创图、三点基地耐久和友弹简化仍按本项目规则，不作逐版本复刻验收。本轮只读原有参考说明，没有新增对外部手册逐项核验的声称。

## 观察与选择

1. **普通开始并观察来敌（目标说明可读）。** 1440×1050桌面、390×844 CSS模拟，均通过可见开始按钮进入第一图单车；停留观察来敌自然攻击。原页面已有基地闪光、爆炸粒子、钻石耐久和“保护信标，清六敌”说明。
2. **首次基地受击（数值正确，事件文字有缺口）。** 两种宽度约00:21时基地降到2格，车辆也曾受击；基地卡片仍是绿色“共享信标”，状态行仍为固定目标。窄屏隐藏手册小字，单靠钻石减少和相似粒子，缺少“是基地受损、应回防”的明确文字。对应本轮四张前后实图，不借旧截图作新证据。这是优先补足核心防守目标反馈的理由。
3. **改善后（同场景信息明确）。** 基地卡片短时标“基地受击”并用现有暖色强调，既有状态行显示“基地受击 · 耐久2/3，请回防信标”。1格时提示“仅剩1/3”；维修更新实际耐久，提示在5个活动秒后退回任务。文字和色彩同时表达，使用已有polite状态区，内容未变时不反复改写。无新增闪烁、遮罩或素材。

## 实现边界

只观察现有基地hp变化，新增很小的展示模型，不写入引擎、游戏对象或存储。准备/重整清理旧提示；暂停冻结活动时间，状态行优先显示暂停；失守或胜利优先显示结局，不残留回防指令。基地耐久增加时更新维修信息，避免旧损伤数字误导。血量朗读标签补全为“基地耐久n，共3”；未作真实读屏听感或完整无障碍合规验收。

伤害、速度、敌人AI与出生、六敌队列、地图、碰撞、随机种子、能力和存档格式均保留。renderer/engine/levels/input/progress不改，原v1/冻结作品、其他游戏及40目录保留。没有扩大到敌人预警、音频、战场重绘或第二项玩法改进。

## 验证

- **普通UI：**本地桌面与390CSS各一次实际首基地受击，显示2/3、卡片提示和状态文字；初始完整玩法快照与基线相同。状态DOM在后续0.3秒不逐帧改写；战场、暂停和反馈行均在视口内，无水平溢出。
- **必要回归：**可见按钮暂停/继续，暂停快照冻结；继续后按原规则自然失守；终局清理提示、重整回待命、J键正常射击、刷新回整备且无旧提示。两宽均通过。仅为触发本反馈的短失败路径，没有重复刷通关，也不据此判断难度。
- **7组Node测试：**区分车体受击与基地损伤、2/3与1/3、持续渲染不延长期限、暂停/维修/到期、准备/终态清理、只读冻结对象；以及30秒正式引擎逐步更新，有/无提示观察的完整快照一致。维修、1格文字、到期和胜利清理包含明确模型fixture，未冒称正常UI触发这些分支。
- 本地页面未捕获异常0、观察到HTTP资源错误0；完整console.error采集在发布后的同组脚本启用，不能把本地未记录项写成全控制台无警告。第一次原生CDP截图脚本在首张截图前Runtime.evaluate超时，无产品结论，保留本地尝试；已有Chromium隔离路线后成功。
