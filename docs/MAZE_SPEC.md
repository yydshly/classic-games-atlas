# 爆破迷宫：第二款固定范围与验收

状态：范围已固定并已实现，验收及部署状态见 [MAZE_VERIFICATION.md](MAZE_VERIFICATION.md)。本轮不开发第三款。

《爆破迷宫 / Ember Maze》参考定时炸弹、十字爆炸、连锁反应与清敌后寻找出口等通用机制。独立原创名称、10 张关卡、角色/场景美术与合成音效，不复制原作素材或关卡。

## 交付范围

- 单人 10 张原创关卡；可破坏货箱、不可破坏结构、可视的锁定出口。
- 放置定时炸弹、十字射线被墙截断、引爆相邻炸弹产生连锁；爆炸伤害敌人及玩家。
- 至少 3 类行为不同的敌人：巡游、追踪、冲刺/停顿；炸弹容量、爆炸范围、移动速度 3 类本关强化。
- 清除全部敌人后到达出口才算胜利，逐关解锁与本地保存。
- 初次教学、暂停、失败重开、关卡选择、声音开关、键盘和触屏；存储不可用时仍可玩并提示。
- 保留 72 条图鉴和堡垒防线；首页区分两款已发布实验和第三款待开发状态，原作介绍与原创作品分开。
- 无账户、联网、后端、榜单、编辑器、付费依赖或新增运行依赖。

## 验收边界

1. 纯逻辑：定时、十字阻挡/破墙、连锁、容量限制、自伤、敌人接触、三种道具、清敌与出口双重条件、暂停、失败/胜利/重开初始状态。
2. 所有十关：尺寸/唯一地图/出生安全区/出口/敌人配置、清除可破墙后的路径可达性，以及首枚炸弹的逃生可能性。
3. 浏览器真实键盘/指针输入：首关及后段代表关卡清敌到出口通关；实际放弹、连锁、自伤失败、重开、进度重载。测试不直接设置胜利或删敌；若仅开放测试选关入口，明确标注夹具，不冒称自然解锁全战役。
4. 移动视口、触屏按键、控制台/网络、帧率样本、返回图鉴与堡垒防线回归；保存截图/录屏或可重复脚本。
5. main 提交与成功 Pages 部署；实际线上游戏地址及核心路径、提交对应文件内容核对，准确列明未覆盖部分。

## 技术与风险处理

继续使用静态 HTML/CSS、ES modules、Canvas 2D 和用户操作后启用的 Web Audio。定步长逻辑与渲染分离。主要风险为炸弹离开后阻挡、自困、同一帧连锁和爆炸多次伤害；在引爆队列、离开许可、网格转向与逻辑测试中明确处理。默认引信给出足够逃生时间，不通过隐藏测试捷径制造通关。
