# 逐款游戏持续交付规则

## 玩家价值与经典玩法参照（2026-10-25 用户确认）

- 先说明玩家扮演谁、要达成什么、主要行动和取舍，以及这一款为何值得做；不能以新增数量、上线或自动测试数量代替质量与可玩性。
- 参考经典作品时先核对可靠的原作资料，在范围文档和游戏开始前明确“参考什么、保留什么、改编/尚未实现什么”。原创角色与素材不等于可以任意替换经典核心体验，也不冒充官方复刻。
- 游戏开始前用普通中文说明角色、目标、操作、成功与失败条件；首次关卡在真实场景中教核心行动，不能只罗列按钮。说明必须与实际实现一致。
- 有疑问先做一关完整可玩切片；逻辑模拟与离线画面仅是证据的一部分，须经过实际浏览器操作和玩家理解/玩法评审，才能决定扩关。单关候选不能标成多关成品。
- 所有已开发作品、入口与旧存档须保全，最终运行能力及必要维护源码/测试集中在主干；不得以某一新作覆盖或丢弃其他游戏。候选分支只作为临时开发和审查载体。

## 开发与交付

- 每款先写短范围与验收，具有多个有设计差异的关卡。当前前两款各固定为 10 关；后续具体范围逐款确定，不承诺一次性完成图鉴全部作品。
- 完整规则包括核心交互、胜败条件、重开、关卡推进/解锁和本地进度。不能以单一空场景或静态截图冒充可玩游戏。
- 原作介绍与本项目原创机制实验分开，原创名称、地图、美术和声音，不提取 ROM 或原作素材。
- 单款游戏作为新增提交与 Web 部署的交付单位。前一款缺陷修复和下一款新增尽量分开提交，并记录各自 SHA 与部署证据；共享首页可随该款同步更新。
- 完成逻辑测试、真实浏览器输入、多关卡覆盖与移动端检查，准确区分逻辑模拟、测试选关夹具、真实操作和未覆盖部分。发现实质阻塞先修复、回归，再推进下一款。
- main 推送后等待 GitHub Pages 成功，在真实网址检查核心路径及文件版本，交付直接试玩 URL、提交、测试证据和限制。未开发或未发布的作品只标为待开发，不能提前标成已发布。
- 每款线上验证后由主对话接续安排下一款；阶段范围结束不表示全部持续开发目标已经完成。不新增账户、联网后端、凭据或付费依赖。

## 持续扩展路线

用户已明确授权持续开发，并在现有作品完成后继续新增优秀经典游戏的介绍与原创机制实验。首批三款属于阶段交付，不是项目终点。继续保留并维护已发布作品，每款先固定完整多关范围、验收、独立提交与上线，再由主对话安排下一款，无需逐款重新向用户确认。每轮按主对话给定的单款范围交付，再接续安排下一款；不因此取消长期扩展目标。
