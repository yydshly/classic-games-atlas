## 问题和修复

公开旧页面通过正常按钮和键盘形成真实存档后，明确注入 `Storage.setItem` 的配额异常；5次写入失败、旧原始存档未变，暂停层仍写 JOURNEY SAVED 和“从保存的位置出发”，没有风险提示。[修复前原报告](before/report.json)与原生截图保留。这是故障注入浏览器证据，不称为实际耗尽设备空间。

`save()` 现在消费 `writeSave()` 的结果。独立持久状态行与暂停说明一致：保存正常、写入失败、原档无法读取而保护，三种情况分开。写失败明确提示本页仍可玩，刷新或关闭可能丢失当前进度；正常写入恢复后自动清除失败提示。重复失败不重写 aria-live 状态，暂停/重试也不显示假成功。坏档继续保留、禁止覆盖，没有新增删除或账户流程。

提示位于游戏面板内，390宽度可见；暂停层也显示风险。没有改规则、关卡、难度、美术、输入时序、引擎、保存键或格式。
