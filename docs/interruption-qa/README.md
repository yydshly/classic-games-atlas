# 三款实时游戏：失焦、后台与返回一致性

**结果：未确认运行缺陷，游戏代码不改。** 基线 `0589f2b6bc98f3f82ff44f53239165cdf6382d13` 的真实公开页面：星泡航线v2、光轨砖阵v2、潮汐珠径v2。三款共15次原生标签切换回合、3次显式继续后的方向保持检查通过。仅追加证据和覆盖索引，不改规则、难度、存档格式、素材、40目录、冻结旧版或停止路线。

## 选择与方法

三款分别代表瞄准/离散发射、连续光球与挡板、连续珠链与150秒活动限时。现有QA已验手动暂停、刷新和失败，未提供本轮完整的可信失焦/隐藏事件链，故不重复成功通关。源码已有失焦清键/自动暂停，不能凭静态逻辑断言缺陷。回声、风行小径、堡垒只读核对后未纳入本轮UI执行；不是重测36项。

本机现有Chromium 147.0.7727.15、Node 22.15.0原生WebSocket/CDP，独立新浏览器profile，1440×1050桌面。通过 `Target.activateTarget` 切换两张真实标签，收集浏览器产生的 `blur → visibilitychange(hidden) → visibilitychange(visible) → focus`，检查 `isTrusted=true`、document.hidden及document.hasFocus。没有改写可见性属性、dispatchEvent、游戏状态、胜负、时钟或存档。普通鼠标/键盘由CDP Input辅助发送；只读诊断导入的是页面script的**同一个完整URL**，使用其已缓存模块导出的拷贝，不重复初始化控制器，不调用引擎动作。

原先Playwright默认会强制页面保持聚焦/可见；空白页切标签/最小化没有可见性事件，不能把它当作后台测试。关闭其附加session的focus仿真后只能产生blur；离屏headed探针也未给出可信hidden。读取现有工具源码确认其内部主session仍开启聚焦仿真后，改用已安装Chromium的独立原生CDP，最终空白探针及三款均产生可信hidden/visible。没有修改工具安装、下载软件或创建服务。一个默认受限路径读取探针未返回，核对父进程任务标记后只关闭该闲置探针；未将其失败记为游戏bug。

## 每款有限流程

1. 准备态切走、等待、返回：仍为ready、活动时间0，不自动开始。
2. 普通开始/确认教程，按住左键并确认可见控制量改变；切到空白标签，在那里释放。游戏自动paused。隐藏期间间隔1.1秒的两份完整玩法快照一致，返回后仍暂停，不无反馈扣时。比较仅排除fps/平均渲染耗时，未排除玩法状态。
3. 点击可见继续：200ms与再500ms后的瞄准/挡板位置一致，没有旧方向粘键。手动暂停后再次切换保持暂停。
4. 正常发射后切走：光球/飞珠、珠链、补给计时及活动时间保持；回到前台不自动继续。原生事件和前后快照均记录。
5. 通过原规则产生一次失利后切换：结果、关段和计时保持，不重开、不跳关。失败策略及读数如下，不能当成无辅助手感或通关成绩。
