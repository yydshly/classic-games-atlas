## 实际公开UI

独立新浏览器上下文，通过普通左右键、X旋转、Space硬降和网页按钮操作。脚本依据只读复制的当前棋盘，在独立Node进程计算放置建议，再发送普通键盘事件；这属于脚本辅助游玩，不是人工反应或手速验收。没有写入存档、胜负、时间、活动块或棋盘，也未调用浏览器中的引擎更新函数。

使用生产requestAnimationFrame与原计时，自然运行21600 tick / 180活动秒；实际墙钟180.109秒，没有暂停、跳时或加速。最终由原规则进入won / reasonCode=time，6106分、38行、80枚落定、最大连消5、速度5档，settlements=1。界面显示0:00和“180秒，收下星光”，结算摘要6106分/38行/最大连消5，个人最好6106分。60/120/175秒及终局均有原生截图；不把阶段截图当终局。

实际319条UI命令另用离线引擎逐tick审计，状态、终因、棋盘、队列、分数、行数、日志、统计等18个所列字段一致，全部不变量通过。[实际UI记录](public-report.json) · [离线审计](ui-log-audit.json) · [审计源](replay_ui.mjs)。离线审计不是另一场实时游玩。

## 刷新与重新开始

1. 自然结算后保存best={score:6106,lines:38,combo:5}、resume=null。正常刷新回ready / 3:00 / 0分 / 0行 / 空棋盘，最佳纪录保留。这符合现有设计：终局记录成绩，不持久保留终局面板。
2. 正常开始新一轮，右移并硬降一枚，得到新局第一枚落定和正分，active.id=2。随后点击“重新开始”，进入全新playing / active.id=1 / 空棋盘 / 0分 / 0行 / 0落定 / 0结算，最佳纪录仍在，held/blocked均空。
3. 稍等后正常暂停，新局35 tick（约0.292秒），再刷新仍先暂停、同一新局checkpoint、空棋盘/0分/0行/0落定/0结算/第一枚；保存原字符串不变，旧180秒局的输入、落块、结算或计时没有回流。

控制台异常、HTTP错误、请求失败均0。本轮未发现需修改的流程缺陷，只补真实证据。
