## 截图判断与唯一游戏内改进

首页已有40项搜索目录，但溪谷19、邮差16不在初始12项中，也没有等价三款上手入口。保留原目录，在它之前提供三种节奏；英雄区分别直达精选与全部40款，纸翼旧版本及冻结项目保持。

溪谷390 CSS准备态要求“先读来敌预告”，但预告顶部实测约1013px，低于844px视口。只在原开始区显示当前关已公开的首个入场时间、行号与敌人类型，并明确准备时不计时、开始后再部署。两场读取同一生产波次数据；不改变排程、费用、冷却、任务、存档或难度。堡垒、邮差游戏代码完全不改。

## 已验范围与真实剩余

1440×1000和390×844普通UI：六条精选往返、两条原目录返回、两场开场预告与刷新；搜索空结果/重置/筛选保留，原生details与焦点、无水平溢出。溪谷/Post通过键盘返回；堡垒通过鼠标返回。三张图完整contain、不裁掉基地/线路/赛道；三款仍candidate_unaccepted。

**下一优先问题已复现：堡垒的全局Enter游戏键拦截头部返回链接。** Enter会恢复/开始游戏而非离开，鼠标正常。源码和原始失败记录见[证据](existing-keyboard-issue.json)。本批限制只改溪谷一项，因此未顺带改堡垒，也不声称全链键盘验收完成。建议下一批最小排除原生链接，保留画布/游戏区域P2 Enter控制。

7组离线检查覆盖开场格式、同时入场/缺数据、重复读取无修改、三个有效推荐版本、旧/新一次性导航收据。一次性导航收据只加可选entry标记，未改任何游戏存档。活动、暂停、终态非ready分支通过控制器精确diff保持原样；本批不重复结局或伪造胜负。完整记录见[test-notes.json](test-notes.json)。

390 CSS是桌面浏览器尺寸模拟；真人理解、手感/乐趣、真机触控性能、声音审美、两人合作及屏幕阅读器尚需人工判断。工具验证不能证明这些品质。

## 维护与复验

`data/featured-play.json`是三卡数据；运行 `python scripts/build-featured-play.py` 更新静态HTML，加 `--check`检查一致。精选不增加运行时fetch、第三方依赖或外部字体。

仓库根运行 `node docs/featured-play-qa/test-featured.mjs`。已有Playwright/Chromium时运行 `python docs/featured-play-qa/verify_browser.py`（本地58251）或加`--online`（公开站）；每次自动创建独立profile，不删除原档。截图使用浏览器原生接口。普通UI脚本没有改写存档、状态或计时；离线fixture不冒充实玩。
