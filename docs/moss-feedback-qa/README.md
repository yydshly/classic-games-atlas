# Moss：真实失散反馈的本地候选

基线main为`02eccbf34a210eea98fa5720c603c14b431e7e19`。本轮只让玩家解释失败、再自行调整救援安排；未改关卡、工具、难度或其他游戏，未发布。Windowlife引导修复仍停止，不启动下一游戏。

## 反馈边界

模型在真实进入下落时附加位置、时刻和该格实际施工者记录，在真实失散时记录原有原因与时刻。它们不参与运动、碰撞或胜负。场景下方持续显示最近一次失散；叉号在活着的同伴下面，不遮队伍。失败结果改为正常文档流，地图仍可见。暂停不清记录；重试、下一关、新旅程使用新世界，文本和标记随之清空。

“桥尚未完工”描述的是开始下落的当时，不拿失散时的桥状态倒推原因。合法只架桥路线中，2号5.60s开始下落，桥5.70s完工，6.25s落水；因此现在桥虽完整，反馈仍能解释先前发生了什么。没有记录足以证明“放行过早”，就不显示这种判断，也不指示某号何时使用何工具。

旧档可继续读取。旧档缺少新增事实时只使用原失足事件和同伴最后位置，不补造施工情形。最近一次记录保留在对应已失散同伴上，事件短列表滚动后仍可回看；它不跨重试或关卡缓存。存档key不变。

## 正常路线前后对照

修前16组合法指令保存在 [before-routes.json](before-routes.json)，来源为固定基线main。新测试从正常初始关卡重放同样指令与0.05s步进，在每条指令后和每步后比较完整状态流hash；仅排除新加的两个反馈字段，全部一致。包括：

| 安排 | 修前/修后相同结果 |
| --- | --- |
| 第一关只架桥 | 4/5，19.80s；多照看挡队则5/5，22.95s |
| 第二关右路开土/自然折返左桥 | 均6/6，分别30.15s/33.80s |
| 第三关不挡队/保护施工 | 分别6/7、31.65s与7/7、35.35s |
| 失足后补救、留下挡员、无输入 | 既有成败、人物轨迹、资源、施工和期限均不变 |

修前首名落水时只出现“已失散”，反馈仍停在出发提示；修后下方会显示实际水隙或高落差原因、位置和有记录的施工情形。希望玩家能解释“为什么这位没回来”，然后自行调整；没有改变通关条件来制造成功。
