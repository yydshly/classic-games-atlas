1. 正常 UI 观察：起跑后赛道只有一条金色高亮虚线；门号在画布左上及侧栏。390CSS 下高亮较小，文字与具体门线缺少就地对应。原来的逆行、路肩和复位警告已经存在，不据此重复改造。
2. 改进：在地图内放置固定12CSS像素的“下一闸门 N”标记，用定位点、引线对应合法目标门线；0号门明确为“本圈终点线”，不暗示已经获胜。仅依当前合法 `nextGate` 取点，不按距离猜目标，不代替驾驶，也不判断玩家是否漏闸。
3. 回归：待命、倒计时、比赛、暂停均展示相应目标；合法过闸更新；刷新暂停恢复同一目标；结算隐藏本批新增标记，重开回1号门。原有终局左上/侧栏下一闸提示保留，不能声称所有终局文案已清理。

## 实际覆盖

Windows桌面、已有Playwright Chromium147，隔离新上下文、冷本地存档；1440×1050与390×844 CSS视口，后者启用移动视口/触摸能力模拟。截图为原生浏览器截图，没有AI图或原游戏素材。

前后图均正常点击开始、W按住4.4墙钟秒穿过3秒倒计时，再松键截图；浏览器调度令活动时间略有差别，并非同一像素帧。图中车辆位置/名次的少量差异不是规则变化。

两种视口各一场第一组合、合法两圈完赛，8种目标门号都被正常经过并观察，16次合法过闸，结算一次。固定公开策略读取诊断副本，每约50毫秒发出普通W/A/S/D；没有写位置、时间、胜负、解锁或存档。此处用于回归标记生命周期，不重复三场全通验收，不把脚本第一名视作真人难度评价。

- 1440CSS：首场17.7333秒，第1名，16次合法过闸。
- 390CSS：首场17.3083秒，第1名，16次合法过闸。

每种视口还检查暂停冻结、刷新后原位暂停且输入清空、倒计时反复暂停/继续、终局隐藏、查看赛场仍隐藏、重开恢复目标/资源且最好与上次结果保留；控制台、页面异常、资源HTTP错误与请求失败均为空。标记不拦截指针；定位点与真实门线投影误差小于2CSS像素，标签留在场地内，无横向溢出。此批正常UI没有故障注入。

7组测试是模型/fixture证据，单列于普通UI之外：所有门/三组合、终局边界、快照输入、冻结对象多次只读、旧checkpoint恢复、30秒有无观察器完全一致、圈线不冒称胜利。

## 下一具体候选与未验边界

正常首场结算后点击“查看赛场”会隐藏结算卡；画面只剩重新起跑等入口，不能再打开该卡中的“下一场”。侧栏仍有上次结果，对手选择仍可进下一场，所以不是成绩丢失或进阶被锁。此状态已由两种视口普通UI与 `afterViewTrack` 可见按钮列表证实；可考虑下一批提供可返回的结算入口，本批未实现。

未验：真机触控/多指、设备性能、真人驾驶手感、反应/注意力收益、审美和声音；未重跑第二/三组合、所有碰撞/漏门/超时组合或跨浏览器。模拟手机不能写成真机验收，有限通过不代表40款成品验收。

复现：已有Node与Python/Playwright环境，在仓库根运行 `node docs/post-feedback-qa/gate-target.test.mjs`；浏览器脚本 `python docs/post-feedback-qa/verify_browser.py --online` 会用隔离上下文正常完成首场，不读取用户浏览器资料。本地模式需在127.0.0.1:58161提供同一checkout静态预览。结果写入 `.local/post-feedback-round`；辅助策略为既有 `docs/post-independent-qa/policy.mjs --stdio`，不执行离线参数搜索。
