# 溪谷v2：左岸附近来敌的行号提醒

本轮只交付一项可见反馈：**在战场旁指出当前靠近左岸的来敌行号。** 基线 `553d82eb56f86d31c8bc7d0c1f05d6853518fb74`。保持经典启发的原创分路防守定位；沿用[现有参考与差异说明](../../versions/v2/games/brook/NOTES.md)，没有新增外部资料逐项核验声称，不使用原作角色/图形/音频，也不作完整复刻验收。

## 观察与选择

1. **准备与普通开始：基本信息已有。** 原卡片明确显示费用、缺露与冷却；侧栏有后续波次时间/行号，画布右侧有短期出生预告，因此本轮不另做资源或波次系统。
2. **约24.2秒，第2行来敌已近左岸：当前威胁缺就地文字。** 同样的首场、1×、不部署观察，两种宽度均通过普通开始/教程让来敌自然移动。原图能看到行号、左侧线和敌人，但390CSS下行号/角色很小，波次列表在更下方，缺少独立的当前临岸行信息。此判断来自本轮真实截图，不用旧通关图代替。
3. **增加一条左岸提醒：** 来敌中心抵达左侧两格及更靠左（x≤100+2×80）且仍存活时，文本显示“左岸附近：第2行有来敌”，并用现有金色系强调。多名敌人按行号排序去重；没有近敌时说明“附近暂无”，不把全场宣称安全。位置提示不预测突破时间或保证某种补救策略有效。

提示靠近画布，在桌面与390CSS均可直接读到；只增加约34px的信息条，不重绘画布、精灵或全页风格。暂停保留实际位置提示；准备、终局和重试更新为对应说明，不保留旧威胁。沿用polite状态区语义，行集合不变时不反复改写文本。没有新增闪烁、声音或自动部署/选行。

## 规则与保存保留

`lane-feedback.mjs`只读当前敌人位置、行、血量和状态，未给引擎加危险阈值或存档字段。临岸阈值仅决定展示，不影响攻击、速度、阻挡、跳跃、资源、冷却、成熟、波次、胜败、150秒上限或重放。engine/levels/renderer/guardians.png保持原对象；原版、冻结作品、其他游戏、素材和40目录保留。

## 已验证与实际边界

- **普通UI，两宽各一次完整有限路径：**初始完整诊断快照与基线一致；正常开始/教程，等实际存活敌人到第2行左侧，提示及完整战场可见、不溢出，不自动改变所选行。连续0.35秒HUD刷新不重复改写同一提示。
- **暂停/恢复与终态：**可见按钮暂停，快照冻结；普通刷新后旧格式重放到同一ticks/time/预算/敌人并先暂停，提示正确派生。继续后未部署，自然在29.7活动秒突破失败；终局清威胁，重复重来两次仍为准备说明且仅一个提示元素。
- **必要业务回归：**通过正常画布点击选格并确认实际行列，部署苔垒/雾环灯/晶枝弩；冷却禁部署，三次花费后70露、雾环灯显示缺25露，C正常收露后可部署。原1×速度保持。没有为了测试改变预算、时间、状态或保存数据。
- **7组Node测试：**显示边界/行号、多目标排序去重、死亡/无效目标清除、暂停及准备/胜败、冻结对象只读、现有checkpoint恢复派生同提示，以及30秒正式引擎有/无提示观察快照完全相同。多行同时接近、目标死亡/离开、胜利等包含模型fixture，未冒称普通UI触发。
- 本地两宽脚本异常、console.error及观察到HTTP资源错误均0。首轮测试在仍选中占用格时错误断言应显示冷却；selectOption路径回到原格，基线与候选相同。原生ArrowDown和画布点击都正常选到下一格并显示冷却。更正为每次确认实际行列的画布输入后重跑通过，失败及短复现本地保留，未为此改产品规则。
