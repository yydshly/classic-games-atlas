## 玩家价值与本关判断

玩家扮演园路员小岚，穿过晨露坡到晨钟亭。关键行动是选择起跳点、起跳速度和按键时长，再在空中收住落点；不是等动画、箱子投掷或拿钥匙开门。叶纹匣出物后还要主动接果；大体型提供一次受击余地。下降踩虫能清除眼前危险并反弹，侧碰则缩小或失败，两个结果有真实因果与现场反馈。

高处需要连续控制落点，能收晨光籽、避开下方巡逻并找到第二颗果实；低处能直接到终点，不需要收齐。大体型吃第二果不会叠盾，因此备用强化只对已缩小者有恢复价值，不能把多拿一次称为新能力。晨光籽只是可选收集记录，目前复玩价值和玩家是否愿意取高路仍未验证。

首关已具备值得真实试玩的完整循环；模型可通关不证明乐趣成立，不以测试数自动决定扩关。后续关数是阶段设计选择，不设用户没有要求的永久三关上限；当前不做第二关。

## 真实UI反馈后的键盘焦点修正（本地）

父线程实际IAB已验证触控短长跳、顶匣接果变大、侧碰缩小与保护圈、小体型碰敌失败、重试、踩敌反弹，以及大体型空中暂停刷新仍保持现场。1280/390宽度可读，无明显大溢出；只推进到首断口约40%，未通关，Shift未实际测。实际运行且画布聚焦时，方向/D和Space/Z无可见动作，P/R和触控有效；没有采样真实DOM key/code/repeat及持时，因此不能把CUA参数名称当事件字段。

已在与发布树相同的本地版本确证一个能造成上述现象的页面缺陷：运动按键过滤使用未锚定的 `/BUTTON|SUMMARY|A/`，其中 `A` 也匹配 `CANVAS`；事件在聚焦画布上发生并冒泡到document时，被当作链接过滤。P/R分支在过滤前，指针又不经过它，解释了它们为何仍有效。输入字段均采用标准DOM事件，没有新增工具映射、注入接口或自动过关路径。

最小运行修复为完整标签匹配 `/^(BUTTON|SUMMARY|A)$/`，编辑控件过滤也改为完整标签；原code绑定、repeat规则、物理/地图/存档未改。标准code配小写/大写key均有效。code为空且只有key的输入当前仍不触发；仅有repeat=true而没有首次keydown也不启动动作，这与清空后需重新按下的规则一致。它们没有被观测为IAB真实字段，暂不为猜测新增兼容分支。

原适配器/真实app夹具直接向document派发事件，即使画布已focus也绕开了真实target，这是此前测试的覆盖缺口。改成向document.activeElement派发后，修复前13项输入/app测试有6项失败；完整标签修复后，34项全部通过，包括两条完整键盘路线、按键释放/失焦/暂停恢复、按钮/链接/说明/编辑控件默认操作不被截走。路线夹具和模型仍逐字段一致。

另在标准聚焦键盘与触控DOM生命周期之间作有限逐帧对照：方向按住72步并穿插repeat、释放24步、跳按住30步、释放落地100步，两个模型状态始终相同；这些是本地固定步时长，不是IAB实测时长。修前/后字段记录和失败日志在 `/workspace/scratch/dawn-hill/keyboard-review/`。本轮只改input、两份测试和此文档共4文件，未动模型/地图/原始输入夹具或其他作品。
