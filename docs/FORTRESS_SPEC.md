# 堡垒防线：本轮需求与验收范围

状态：首款实现完成，本地逻辑与真实输入验收通过；部署终态见 [FORTRESS_VERIFICATION.md](FORTRESS_VERIFICATION.md)。本轮不继续开发后续游戏。

## 产品边界

《堡垒防线 / Beacon Bastion》是参考坦克移动射击、保护基地、破坏砖墙与拾取道具等通用机制的原创单人游戏。名称、10 张关卡、美术和合成音效均为本项目创作。不提取 ROM、原作图片/音乐，不逐关复制《坦克大战》，不将其称为原作完整复刻。

- 25×25 网格战场，连续移动/转向，方向键或 WASD，空格/J 射击。
- 10 张各有地图布局和敌人组合的原创关卡，逐步提升兵力、装甲与同时来袭数量。
- 可破坏砖墙、不可破钢障、阻挡车辆的水域；基地 3 格耐久，玩家 3 次出击。
- 侦察车、突击炮、重装车至少 3 类敌人，速度、耐久和火力有差别。
- 维修、护盾、速射至少 3 类道具，清楚显示生效与剩余时间。
- 初次教学、暂停/恢复、重开、胜负结算、逐关解锁、localStorage 本地进度、声音开关。
- 键盘与触屏控件；切出页面自动暂停。无需账户、联网玩法、后端、榜单或编辑器。
- 保留 72 条图鉴及其搜索/筛选/详情；坦克大战条目关联原创作品，原作和实验分开标识。

## 视觉与交互目标

统一的深色复古街机界面。车辆具有履带、车体、炮塔、装甲标识和方向反馈；墙面、钢障、水面与信标可区分。命中、爆炸、出生保护、基地损坏、道具和胜负均有反馈。避免以无贴图矩形作为成品美术。不宣称审美获得用户验收。

## 验收清单

1. Node 无依赖测试：10 关尺寸、唯一地图、敌人配置、出生点、基地/玩家位置、钢障/水域条件下的路径与可达性。
2. 逻辑测试：车辆碰撞、砖墙受击和破坏、钢障阻弹、敌人不同耐久/行动、玩家与基地受击、胜败、暂停、重开所需初始状态、3 类道具。
3. 浏览器真实输入：通过鼠标/键盘进入首关、移动/转向/开火、实际敌人交战，完成一个完整回合；不通过改写游戏状态制造结算。
4. 浏览器 UI：教学、暂停/恢复、重开、选关锁定与解锁、本地进度重载、声音偏好、触屏控件、返回图鉴；模拟逻辑验证和真实操作证据明确分开。
5. 桌面/手机视口、帧率采样、控制台与资源请求；保留截图、首关真实输入录像或可重复脚本。
6. main 提交、Pages 成功构建；真实线上 URL 验证游戏入口、核心游玩路径与资源版本一致。

## 实现结构与风险

使用 ES modules 与 Canvas 2D，无构建步骤和新增依赖。逻辑固定步长，渲染与逻辑分离，地图为可审阅的数据。音频仅在用户手势后启用并使用 Web Audio 合成。

主要技术风险是狭窄通道碰撞与敌人寻路、移动浏览器焦点/滚动和后台标签计时。以网格对齐转向、可破墙路径规划、指针捕获、清空失焦输入与自动暂停处理，并在验收中覆盖。localStorage 不可用时保持本局可玩并提示无法保存。
