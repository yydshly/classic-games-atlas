1. 普通UI先确认：安全与体验区别、目标数值和逐段错误原因已经存在。缺口在诊断定位：原“查看1号段”只选段并把焦点送到轨道索引，未显示修改操作。390CSS下焦点约在−638px，修改标题约−1802px，仍看着诊断报告；桌面提升按钮也在视口下方。

## 正常UI：两次失败、两次明确修正、一班收入

Windows桌面已有Playwright Chromium，隔离新上下文；1440×1050与390×844CSS视口，后者为移动/触摸能力模拟，不是真机。所有方案、试车、定位、装模块、载客及返回设计均由普通按钮或原生按键完成；只读诊断副本观察，没有写游戏状态、现金、时间、方案、存档或胜负。

每种视口均执行同一有限首园链路：

- 初始普通轨空车试跑，在1号爬升段自然失速，测到1/12段；开放按钮禁用。鼠标点击诊断定位，段号01/12与名称、整个模块面板、提升和制动按钮均可见。模型与资金、报告和收益不因定位改变。
- 从面板按Tab到普通轨，再Tab到链条提升，按Enter明确安装。建造160，旧报告失效，开放仍禁用。没有自动装模块或自动开园。
- 再次自然试车到12号段，因回站速度16.5大于12未通过。键盘Enter激活该条诊断，正确定位12/12与站前进站段，显示完整修改面板及3px键盘焦点环；报告与资金保持原值。明确点击站前制动后建造220、余额160，报告再次失效。
- 第三次空车自然跑完全圈，安全与体验通过：刺激约33.2、舒适约97.2，12/12段完成；试车仍为0载客班次/0营收/0口碑。此时开放按钮才可用。
- 正常开放后只等第一班完整回站：8位游客、营收128、口碑74、1班。正常返回设计，放弃下一班未结算部分，已完成收益仍在；刷新保留方案、认证和这一班结果。

这是失败→读诊断→定位修改→安全通过→一班营业的实际链路，不是再跑八园通关，没有取得本批新通关票根或解锁。两模块思路来自既有公开方案，不把它说成无辅助的新手自然发现。既有八园完整证据仍在coaster-later-qa。

最终两个视口全部通过，修改面板及提升/制动操作完整在视口内，无横向溢出；页面/控制台异常、HTTP/请求失败均为空。原有安全/体验说明未重写。
