基线 `abde6a4172967426b54307bd6dae2b4d9b292464`。只修结算卡的返回流程，不修改驾驶规则、速度、AI、赛道、排名、存档格式或40项目录。

1. 已证实问题：自然完赛后点“查看赛场”，结算卡与其中“下一场”按钮隐藏，却没有重新打开的入口。侧栏上次结果和对手选择仍在，故不是成绩丢失、未解锁或不能继续游戏。
2. 最小修复：赛场顶部在“已结束且卡已关闭”时显示“返回结算”。关闭卡后焦点移到这个按钮；按Enter可重开，焦点回到结算主按钮。Tab可由返回入口到赛场，再Shift+Tab回入口。查看赛场保留，非终态入口隐藏。
3. 重新打开直接显示原卡，不再次调用结算、建局、保存、最好成绩或解锁逻辑。进入下一场/重赛沿用既有动作与规则；界面状态改变不会持久化新的字段。刷新仍按原设计恢复活动局，已结束刷新回准备界面，不新增终局持久化。

## 普通UI覆盖

Windows桌面已有Playwright Chromium，1440×1050及390×844 CSS视口，隔离新上下文；窄屏启用移动/触摸能力模拟，不能视作真实手机。每个视口只跑第一场一次合法两圈、16次过闸，自然结算一次。沿用公开只读策略，每约50毫秒根据诊断副本发普通W/A/S/D；不注入位置、时间、胜负、解锁或存档，也不重跑三场全部胜利。

每个视口进行5次关闭/重开：第一次点“查看赛场”，随后使用Tab、空格、Enter；关闭焦点为返回按钮，重开焦点为结算主按钮。完整游戏快照与存档原字符串保持一致。按钮位于视口内，无横向溢出；待命、倒计时、比赛、暂停均不显示返回入口，终局卡打开时也隐藏。

- 1440CSS：从重新打开的结算主按钮正常进入第二场；0计时、0结算、三车未完赛、0过闸，焦点回赛场，返回入口隐藏。再暂停并重赛当前第二场，保留首场最好/上次结果/2场解锁，短暂正常驾驶后暂停刷新同车位接续。
- 390CSS：终局直接点击原有重新起跑，回第一场准备；资源/计时/结算复位，最好/上次结果/解锁保留；正常起跑与短暂驾驶、暂停刷新通过，返回入口仍隐藏。

没有故障注入。控制台、页面异常、HTTP资源错误及请求失败均为空。自然结算后的五次开关不改变游戏与存档；“没有额外setItem调用”由下面的独立控制器计数测试证明，浏览器字符串不变本身不证明零写入。

## 控制器fixture，与实玩分开

7组Node VM测试执行真实控制器源码，替换DOM/渲染与初始终态夹具，并使用真实引擎方法。覆盖20次开关及期间帧更新，保存调用/建局/checkpoint调用次数、成绩和解锁都不增加；下一场与重赛只沿用原本建局和两次保存；第三场重赛无第四场；超时卡可重开但不授予完赛或解锁；非终态即便直接调用事件也无效。超时、最后一场和其余组合是fixture证据，本批没有冒称自然通关它们。
