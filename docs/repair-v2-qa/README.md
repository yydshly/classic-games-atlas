# 雨街修理所 v2 · r2 营业反馈候选

2026-10-18。独立路径 `versions/v2/games/repair/`。这是可供公网实测的候选，不是成品验收。

## 本次范围
- 原 v1 房间、八日规则、费用、耐心、工资、排队路线、关卡与记录边界保留。engine.mjs / levels.mjs 与基线逐字节一致。
- 原创离线 Blender 建模：4 类机器人各 4 帧步态，3 类技师各 6 帧（4 步态、2 工作姿态），合为单张 788421 字节透明 PNG atlas。
- 诊断扫线、机械工具接触/齿轮、电路焊接火花依据真实 servicing 工序触发。队列序号与耐心条取真实队列；金额只在实际付费离店时显示。
- 桌面选中工位操作坞与画面并排；窄屏坞紧贴 A–F 按钮，包含真实所选工位裁切近景、进度、排队、升级/保养/建造，技师调度折叠。
- 全店与近景使用游戏 elapsed 时钟，暂停冻结；减弱动态偏好时两者都停止特效动画。
- 工位和人物统一深度排序，后排台后的角色不再画在设备前。精确补偿素材透明留白，脚底与路径锚点对齐。

## 已验证
40 组引擎、10 组存档、29 组实际控制器（DOM替身）、1 组路径/键隔离、5 组实际renderer测试通过。八天使用合法按钮等价策略全部胜利。所有 .mjs 语法检查通过。测试与日志见同目录 checks.json、logs 与 validation/repair-v2。

## 验证边界与待验
- 同状态 renderer 图及 26 秒序列是实际引擎自然演进、相同页面 renderer 的离屏输出，不是浏览器录像。
- 本执行器 Chromium 的 socket 启动被沙箱拒绝，提升后 bwrap 又报只读路径，未绕过限制。没有本地/公网浏览器截图，未做真实手机或音频验收。
- 上线后必须实测 400/500/1180 CSS 宽的准备、营业、选位/建造/派驻、暂停、恢复、导航与资源加载。CSS 的同屏意图不能当成实测证明。
- 全店背景仍是 v1 的平面插画，人物采用预渲染2.5D，仍非全3D；首两天经营深度与后六天耐玩性没有扩大验证。当前没有新增音效。

## 探索记录
r1 使用较亮金属材质，机器人与平面技师/房间不协调；脚底透明留白产生约7像素视觉浮起，原先全工位先画/全角色后画造成后工位遮挡错误。根目视指出后做 r2：低金属/高粗糙度、弱暖光、技师同材质、脚锚补偿、工位/人物按真实y排序。
r1 原始 PNG 被同名覆盖，无法作为原始证据再交付；不伪称完整保存。首轮构造脚本和材料参数另留本地记录。r2 图片、状态快照和26秒序列已按版本封存；视频与原始帧不进入站点，避免部署膨胀。

## 素材来源与重建
模型全部由本轮脚本用基础几何体原创构造，没有外部下载、角色IP、付费采购或AI图片。Blender 4.3.2，Cycles CPU 6线程，192采样，无去噪（此构建不支持 OpenImageDenoise），256×320 RGBA透明帧，正交相机。材质/光照/相机参数完整见 source/render_robots.py、render_technicians.py。运行两脚本后以 pack_atlas.py 合成6列图集。
