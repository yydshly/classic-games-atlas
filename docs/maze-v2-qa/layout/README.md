# 爆破迷宫 v2：本地布局修复，未发布

基线：`99af2f7fa3768968f19d19a2ae9c66d848857e5f`。本轮只修改迷宫 v2 的布局与必要焦点，不提交、推送、部署或创建PR，也不开始第三款。原工作区与堡垒隔离检出保持不变。

原始实际浏览器基线中，1165×747 顶部视口的棋盘下缘约921px、放弹按钮下缘约1036px；滚向控件后暂停按钮离屏。390×640 的放弹按钮下缘约663px。原尺寸截图与基线报告保存在 `.local/maze-layout-qa/before/`。

## 修改

- 原11:9棋盘在独立区域内按可用宽高等比缩放，完整显示所有行列；关键操作使用视口高度预算。
- 双方炸弹容量移到计时HUD；短屏压缩方向盘，横屏将HUD与操作放右侧，320px窄屏使用单行方向键以保留棋盘尺寸。
- 次要规则、选图和记录仍可在下方/侧边阅读。侧栏切图后回到顶部并聚焦开始按钮；暂停继续后焦点回棋盘，J放弹正常工作。
- 开始/暂停/结果卡在棋盘区域内限制高度并可滚动，短屏使用紧凑卡片。原≤600px“卡片进入文档流”静态CSS契约已被新的视口适配取代；`test.layout.mjs`改为HUD唯一ID、控件标签和原始棋盘分辨率的语义检查，实际几何由浏览器验证，不用静态算式冒充布局验收。

引擎、AI、2.4秒引信、难度、两张地图、Renderer、美术及旧十关内容不变。

## 本地验证

`node --test test.engine.mjs test.layout.mjs`：14项原规则检查及2项语义结构检查通过。没有重跑或把48场引擎模拟当作本轮实玩。

`test.browser.py`：实际 Chromium 页面自动化，1440×900、1165×747、1280×600、390×844、390×640、320×568、844×390共7种视口。检查完整棋盘、计时/炸弹容量、暂停、四方向与放弹同屏、未横向溢出；主要控件至少44px，棋盘格宽约27–62 CSS px，保留11:9比例。最终报告及原尺寸截图在 `.local/maze-layout-qa/after/`。

每种视口都通过正常键盘或CDP触控执行：开始→暂停→按钮继续→右移到(3,3)→J或放弹按钮→退回(1,3)→上转到(1,2)→等待自己的炸弹爆炸并存活。只读diagnostics观察位置和引信；不调用引擎update，不写地图、AI、时钟、生命或结果。

另验证暂停完整快照冻结、重试清空战局、两图切换、侧栏选图回到顶部与开始焦点、刷新回默认图READY，以及页面实际v1十关链接。刷新不是战斗续档。最终控制台、HTTP错误和请求失败为空。

首轮完整检查的7个迷宫视口已通过，但旧版入口因稀疏检出缺少其原有 `versions/v1/games/fortress/fortress.css` 导入而出现404。从同一基线补齐未改动的原CSS，并调整横屏按钮换行后，保留失败报告，完整复验一次通过。
