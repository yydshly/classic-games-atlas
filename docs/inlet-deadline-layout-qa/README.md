## 源码原因与限定修改

桌面原play-layout把说明置于右栏，海图列又把状态、海图、操作纵向堆叠；完整海图宽度决定的高度加上说明/页头，容易把状态与按钮分到视口外。
移动run-controls是flex-wrap；phase-label却只设置grid-column，对flex无效。按钮flex:1默认可收缩，CJK的min-content可到单字宽度，因此阶段提示与三个按钮挤进窄draw-console列时出现竖排。

本候选：
- 保持全部既有操作子树，仅将状态、操作、预览归到海图旁的play-console。非操作说明移到游戏区后，桌面海图按视口高度约束宽度，仍保持11:8比例，不裁切海图。
- 小屏按“标题→状态→分区目标→海图→主要操作→方向预览”排布；状态条可随滚动保留。预览卡片不占海图列，也不先于操作挤占高度。
- draw-console仅display:contents参与排版；run-controls使用全宽行，phase-label独占一行，按钮min-width5rem、flex-shrink0、white-space:nowrap，按完整按钮换行。方向键仍至少44×44。
- 原试玩边界说明改为原生details，未UI验收与隔离存档摘要始终可见，原全文保留可展开；存储错误#save-warning独立保留，没有折进说明。原脚本已支持summary保留原生键盘事件。
- 没有修改任何脚本字节、按钮事件、文字状态、规则、保存key或输入逻辑。
