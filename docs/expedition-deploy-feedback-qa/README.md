# 苔原远征v2：调兵前看清来源与空防代价

基线 `2e1b104031bcb9a2ba04a4ca7c27b68722689619`。[试玩](../../versions/v2/games/expedition/) · [前后截图](./) · [覆盖索引](../flow-coverage/)

## 普通UI确认的问题

推荐版仍是v2；既有三段胜利、失守、重试与暂停记录保留。本轮全新独立profile只用开局2名盾卫：两人从营地去北口，抵达后向南口抽调1人；两线各1时再向北口调1人。原按钮只写目的地，说明只提“营地新兵”，没有事先展示跨线来源、7秒行军或抽走最后一人将空防。操作后各线人数和地图行军能看见，但不能代替下令前的决策信息。这是理解缺口，调兵算法本身正确。

## 最小改进

现有按钮内显示实际来源、调动人数、行军秒数及来源驻守前后值；来源防线将降至0时标“将空防”。目标显示“现驻N卫；本次抵达+1”，不把行军中的部队提前算作驻守，也不承诺其它在途单位同时抵达后的总数。无兵可调时保留禁用并显示原引擎原因。

预览在独立副本上执行同一个生产command，读取真实选中的单位；不复制调兵优先算法，不推进模拟，不向当前游戏发命令。营地优先、同优先级按单位id、4/7秒行军均仍由原引擎决定。没有新增确认步骤、改变指令、数值、关卡、资源、存档格式或自动调兵。样式仅限调兵按钮小字。

## 实际验证

- 修复前4次、修复后6次普通UI调兵；自然运行不足一段，不追求通关。预备队足够/为0、全员在途无可调兵、两线各1、跨线空防、将一卫调回营地后优先用营地增援均验证。操作后原有各线人数和行军量正确。
- 桌面1440×1000与390×844截图、Enter下令；刷新先暂停，重新打开防守面板时checkpoint原字节、余量、预览一致；暂停按钮保持禁用调兵，继续后恢复。
- 原生Tab/ShiftTab与可见焦点，跨模拟render后仍保留焦点且按钮在视口内；这组复查未发新调兵命令。
- 8组测试：审计10次真实UI指令的实际选人；营地足够；不足时count2混合来源；同值两线id顺序与空防代价；行军/已驻目标/已阵亡排除；不足及无效请求无部分抽调；ready/paused/terminal；20次预览不改游戏或旧格式checkpoint。

count2批量请求只属于离线边界，界面仍每次1人；阵亡和终态用合法离线引擎自然推进验证，不能混称浏览器实玩。初次批量断言误把返回列表顺序当抽调先后，已修正测试并保留说明，没有改规则迎合测试。

`node docs/expedition-deploy-feedback-qa/test-preview.mjs` 可从仓库根运行。verify_browser.py/verify_keyboard.py为本轮内部实测脚本，使用既有Playwright和独立profile；运行前阅读test-notes.json。无需且未安装依赖。
