# 三款精选：原生触控仿真与一项输入修复

基线 `c66befb195f638e1731e139947fb168d9a21f066`。[试玩](../../#selected-play) · [截图](./) · [既有证据复用判断](evidence-review.json) · [下一产品里程碑提案](next-milestone.json)

这是安装环境已有Chromium的触控模拟，**不是真机验收**。390×844、mobile/has_touch、5触点仿真；使用CDP原生触点输入，而不是鼠标click或DOM伪造指针事件。事件只读记录确认pointerType=touch、isTrusted，后者不代表物理硬件。没有注入游戏状态、计时、胜负或保存数据。

## 三款有限流程

|邮差v2|触屏三秒起跑；同时按油门+左转；部分松指保留剩余控制，移出捕获区再释放；双指cancel；暂停/恢复/返回；边缘滚动0→375|流程正常，代码不改。补录实际车头角0→约−0.5673、速度0→约58.48；不是比赛胜利|

[三款公开基线全记录](public-baseline.json)中触点down分别10/10/9次，cancel分别2/2/3次，均有原生touch轨迹。中途出现按原规则自动复位，未据此推断手机难度或调参数。邮差放开控制后有既有惯性；以触点映射归零和实际释放事件判断，没有把车辆继续滑行当粘键。

控件激活前检查中心点未被遮挡；测试准备时部分控件用scrollIntoView带入视口，因此不宣称全流程始终同屏。独立页边缘真实触控滑动可滚动，控制区长按/移出期间不抢滚动，画布取消不触发部署。未穷尽所有多指/手势组合、浏览器栏变化或系统手势。

## 唯一修复：输入有来源，松开只释放自己的来源

公开页两根手指按住开火，第二触点pointerup/lostpointercapture后，第一个仍无up/cancel且保持按住，520毫秒内射击数8→8。原输入只按键名保存，任何触点释放都会删掉同名键。现在记录键盘及每个pointerId的来源；最后一个来源释放才松键，pause/clear清空全部来源，重复lost-capture不清掉别的持有者。没有改变射速、弹药、移动优先级、引擎、关卡、存档或布局。

[本地堡垒复验](fortress-local.json)中剩余手指继续射击（增加1次），全部松开/取消无残留。追加普通W/J、P2 Enter、键盘按住与触点释放混用正常。旧键盘默认press/release/clear序列1200步与原类的方向/开火结果及顺序完全相同；[7组来源测试](input-tests.json)与[此前50条控制器回归](keyboard-regression.json)分列，模型不冒充实玩。

溪谷、邮差已在公开基线上完成本批所需触控流程，代码树发布时精确保全，不再重复同等流程。只有堡垒需要修复后的本地和线上复验。

## 方法及边界

先在独立about:blank[原生探针](native-probe.json)校准部分抬指，保留最初适配器错误，不把其错误释放当游戏缺陷。采用本机探针验证的路径，API说明见[DevTools Input协议](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json)；跨浏览器兼容性不由此保证。游戏轨迹与探针明确分开。[邮差角度补录](post-heading.json)仅补首轮未保存的实际转向增量，没有再刷暂停/取消或比赛。

运行 `node docs/featured-touch-qa/test-input.mjs`（Git checkout/Node）；已有Playwright/Chromium时，从仓库根运行`python docs/featured-touch-qa/verify_browser.py --mode verify`。默认公开站，`--base`可指定预览，`--only fortress`只复验受影响游戏。新profile保留，不动原存档、不安装依赖。

本轮没有真实移动设备、多指人体工学、触控延迟/性能、操作系统切后台/手势、两名真人合作、屏幕阅读器、声音与审美验收。后续建议转向**一款连贯的五分钟合作短战役**，先给可玩的产品链与真人评审，不继续无限泛化QA；该提案尚未实现。
