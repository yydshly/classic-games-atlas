# 草甸联赛 v2 · 一轮有限可玩预览

2026-10-18。本候选承接第 40 款未完成项目；恢复代码不等于已发布 v1。它是独立的原创 3 对 3 围场足球预览，不是完整 PES 复刻或成熟足球游戏。

## 这一轮做了什么

- 保留原草甸、看台、六名球员和动作插画，不以新几何草稿替代已有美术。
- 修复自动门将在近目标时低速意图被再次归一化为全速的问题。双方使用同样的规则；八场时间、AI反应、球速、球门、风雨参数没有改动。
- 脚下金环表示实际持球人，白环表示控制对象，虚线环表示唯一可传的队友。短箭头使用与射门相同的方向函数，只显示出脚方向，不预告能否进球。
- 外部球权文字使用真实球衣号 7/11/9/6；修正原说明把深蓝主队称为绿色的错误。
- 手机上仅裁去画布重复的内置比分和底栏，保留整个球场、两球门；网页比分、球权与操作按钮仍在。开始/继续时把球场带入视野。这项布局仍需要公网浏览器验收。
- 独立存档键 atlas-v2-meadow-20261018-progress-v1 / current-v1，不读写恢复版或其他版本进度。

## 玩法与来源价值

原页面声明 PES 风格，未指定具体代际。核心取舍是看空当、带球吸引防守或转移给队友、把握蓄力射门窗口，以及失球后切人回防。J 是传球/抢断，K 切换两名外场球员，门将自动。

两种可以理解的思路：
1. 边路带球：沿边路推进再回到球门侧前方，停稳或面向右方，短蓄力射门。
2. 传球转移：带到一侧吸引追防，J 交给另一侧接应者；控制会跟随接球人，等球到脚下再找角度射门。

没有越位、犯规、界外球、点球、常规角球、十一人制阵型、独立二过一指令或专业运动员能力模型。围栏反弹、8 场短局和风雨条件为原创简化。

## 本地验证

所有模拟从公开开局开始，战役不给角色位置、比分、球权或输赢赋值。

- 引擎 45 组；进度 122 断言；真实 game.mjs 控制器 73 组；v2 专项 6 组。
- 100 ms 决策的 DOM 键盘/触点事件替身完成 8 场并自然解锁：3:0、5:0、10:0、10:1、6:3、15:0、13:1、7:1。传球、抢断、射门、门将扑救和结算均来自引擎。
- 另一次 300 ms 公开引擎输入全赛程：3:1、2:1、3:1、3:2、6:2、8:1、2:1、8:0。它不是 DOM 全赛程测试；300 ms DOM 试跑曾在第三场 1:3 失败，不能据此宣称所有控制节奏都已通关。
- 首场两路线的 300 ms 结果：传接 3:1，有 12 次传球；边路 6:3，0 次传球。无操作 0:5，持续向后 0:3。
- 原单带球脚本在雨后 3:3；改用传接路线能赢，并未削弱该场参数来迁就测试。单一脚本胜负不等同于人的难度体验。
- 仍有 15:0 等大比分，AI分球和开球可被熟练脚本利用。没有称难度平衡已成熟。
- 暂停/继续、重赛确认取消、帮助/赛程窗口、焦点离开、取消触点、刷新暂停恢复、坏存档、存储拒绝和隔离键都有自动检查。

## 公网验收清单

1. 打开 index.html，开始比赛；主队深蓝、向右、金环球权、白环控制与箭头一致。
2. 正常传球并接到，移动、按住/松开射门；完成一场到自然胜负。确认不存在控制卡住或自动获胜。
3. 手机 400×844：开场后同时能见球场、球权与操作；两球门未裁去、页面无横向溢出。方向与射门可同时触控，拖出和取消不会误射。
4. 暂停、帮助关闭、重赛取消、后台返回与刷新均保持暂停；点击继续后才推进。
5. 胜利解锁后刷新仍在；v2 不改其他游戏或旧恢复项目的存档。

这些公网、真实设备和人工体验项在本地候选阶段尚未通过。有限轮收口，不继续无边界增加球队、素材或足球系统。
