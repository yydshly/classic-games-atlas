# 灯下候诊 · 三班经营原型

这是一款原创、可独立存档的三班短篇诊所经营实验，不计入图鉴既有 45 款正式目录作品。所有人物、建筑、图形和“失拍光／漂影”病症均为虚构；它不是医疗模拟或现实医疗建议。

## 经典启发与边界

[Electronic Arts 对初代《Theme Hospital》的官方介绍](https://www.ea.com/games/theme/theme-hospital)强调在有限资源下设计、维护并经营医院，让诊室、员工和病患流动互相牵动。本作取这一经营循环为启发。为什么这种循环有吸引力，是设计推断：每次扩房或增员会改变下一批来者的等待与财务，玩家能看到短期收益和后续拥堵的关系；这里不声称复现原作的人气数据。

本作主动缩减为四个房位、两种虚构处理室、一间可选读谱室、最多两名护理员和三班固定排程。没有商业原作的病名、角色、建筑、美术、音频或关卡，也不宣称是完整复刻。误送只带来灯票、时间与排队代价；无真实病患伤害或随机医疗结果。

## 核心循环

每班先选建房种类，再点四个房位规划。近房使来者少走路，但近房只有两间；调频与稳光室需要护理员，读谱室花时间确认模糊线索。点“推进 1 分钟”后，来者按固定时刻出现（页面不预告精确到达分钟），接待台每分钟登记一位。看线索，可直接选择处理室，也可先读谱再安排。护理员同一分钟只照看一室；增聘第二人花 8 灯票。成功处理 +5，误送 -2 且会公开类型，等待超期会离开。开班前拆房全额退款，开班后只退半价；在途来者会回到待安排队列。

三班递进：暮港首诊教明确线索和房位；雨棚拥诊在读谱确定性与第二护理员的速度之间取舍；双翼夜班增加来者密度和远房路程压力。分别须在 12／12／13 分钟内处理至少 3／5／6 位，离开至多 1 位。不同路线可同样过关，但分钟数、灯票和误送记录不同；不把一条脚本路线当成陌生玩家觉得好玩。

鼠标或触控点按；键盘 Tab／Enter 可用全部控件，N 推进一分钟，P 暂停。自动保存于 `classic-games-atlas:lantern-clinic:v1`；刷新后先暂停。失败可重试当前班，取消不会写档，已解锁班次与之前的成绩保留。坏存档拒绝载入，不读取或改写其他游戏的键。

## 本地验证

在仓库根目录启动本地静态服务器，打开 `/experiments/lantern-clinic/`。`node --test experiments/lantern-clinic/engine.test.mjs` 覆盖三班、两种计划、成本、软锁恢复和存档。私有 `.local/lantern-clinic-qa/` 是原始截图与浏览器记录，不纳入发布。三班键鼠与 390 原生触控正常操作已有限走通；真人首玩、实体手机和长期重玩价值仍待验。
